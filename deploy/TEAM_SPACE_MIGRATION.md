# 团队知识空间升级说明

此版本仅允许飞书登录，新用户申请加入空间 10000；审批人批准时必须选择角色。初始 Owner 仅由飞书返回的邮箱 jordyn.ji@idreamsky.com 匹配，每空间仅初始化一次，不依赖本地用户 ID。

## 发布前

- 确认空间 10000 已存在且状态为 active；本版本不会创建替代空间。
- 配置 FEISHU_LOGIN_ENABLE、FEISHU_LOGIN_APP_ID、FEISHU_LOGIN_APP_SECRET，登记准确的后端 /api/v1/auth/feishu/callback 地址。
- 确认飞书应用已获用户基础资料及邮箱读取权限，目标账号授权后可返回 enterprise_email（优先）或 email。
- 停止旧版本实例接收请求，再备份数据库及正常文件存储。不得让仍查询共享表的旧实例与新版本迁移同时运行。

## 迁移与验证

新版启动时按现有迁移机制执行 PostgreSQL 116/117 或 SQLite 36/37：创建 tenant_join_requests，删除 organizations、组织成员/申请、kb_shares、agent_shares 和 tenant_disabled_shared_agents 等历史关系。知识库、智能体、文档、会话、正常成员和文件本体保留。

1. 使用初始化邮箱通过飞书登录，确认获得 10000 的 Owner，成员管理能看到申请审批区。
2. 使用另一飞书账号确认只产生申请，无个人空间；批准时角色必选，获批后无需重新登录。
3. 确认旧共享空间和分享接口均不可用，正常知识库、检索、对话、文件及机器集成可用。
4. 确认普通用户不能创建空间，拒绝/移除成员不会通过再次登录恢复权限。

## 回退

共享关系清理属于数据删除，不能靠应用降级恢复；需要恢复升级前备份。申请表中的 feishu_bootstrap 标记必须持久保留，常规降级不得清空该表，否则可能再次初始化 Owner。

本说明仅描述部署步骤；代码变更本身不会连接或迁移生产数据库。
