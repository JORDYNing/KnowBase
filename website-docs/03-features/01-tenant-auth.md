# 团队知识空间与飞书认证

本项目使用飞书登录和管理员审批加入团队知识空间，默认目标空间为 **10000**。新账号只创建身份，不创建个人空间；普通成员不能创建知识空间。具有 `CanAccessAllTenants` 的既有平台超管，以及具备 `system_tenants_manage` 能力的平台 API Key，保留平台空间管理能力。

## 登录与申请

1. 在登录页点击飞书登录，通过飞书授权完成身份认证。
2. 首次登录自动提交加入 10000 的申请，账号暂时没有空间访问权限。
3. 等待 Owner 或 Admin 审批。拒绝后可查看原因并手动重新申请，重复登录不会自动重提。
4. 获批后页面自动刷新空间凭据，无须再次登录。

待审批页仅在前台可见时每 30 秒查询状态，也支持手动刷新和退出登录。目标空间缺失、停用或服务异常时页面显示可重试状态，不创建替代空间。成员被移除或暂停后，再次登录不会自动恢复权限。

密码登录、公开注册、邀请注册、OIDC 和桌面自动登录均已关闭，旧配置不能重新启用。API Key、MCP 和嵌入渠道的机器认证继续使用现有能力与资源范围约束。

## 初始 Owner

唯一初始化匹配条件是飞书服务端用户资料返回的邮箱 `jordyn.ji@idreamsky.com`：优先 `enterprise_email`，缺失时使用 `email`，去除首尾空格并忽略大小写。本地用户 ID、前端参数和本地个人资料邮箱不能代替该校验。

账号通过飞书认证且目标空间有效后，在数据库事务内授予 Owner，并写入 `source=feishu_bootstrap` 的永久申请记录。数据库限制每空间只能初始化一次；之后修改角色、撤权或邮箱重新分配均不会再次授予 Owner。该操作不授予系统管理员身份。

## 审批与角色

批准时必须主动选择角色，没有默认值。

| 审批人 | 可授予角色 |
| --- | --- |
| Owner | 只读成员、贡献者、管理员 |
| Admin | 只读成员、贡献者 |

只读成员查看团队内容并使用允许其运行的智能体；贡献者可以创建知识库和智能体、编辑自己创建的资源；管理员管理空间内容与配置。Owner 身份通过已有所有权管理流程调整。

申请按用户与空间唯一存储。重新申请增加版本号，审批校验版本；成员关系、所选角色和审核结果在同一事务写入。相同审核请求重试不会重复授权，旧版本审核和冲突决定会被拒绝，审核历史写入审计日志。

## API

所有接口位于 `/api/v1`，用户接口使用飞书登录获得的 JWT。

| 方法与路径 | 用途 |
| --- | --- |
| `GET /auth/feishu/config` | 查询飞书登录是否可用 |
| `GET /auth/feishu/start` | 发起飞书授权 |
| `GET /auth/feishu/callback` | 飞书回调，完成身份与申请处理 |
| `GET /me/tenant-join-request` | 查询本人申请及目标可用性，无空间账号可调用 |
| `POST /me/tenant-join-request` | 失败重试或被拒后重申；重申提交当前 `version` |
| `GET /tenants/10000/join-requests` | Owner、Admin 分页查询申请 |
| `PUT /tenants/10000/join-requests/:request_id/review` | 提交 `approved`、`version`、可选 `message`；批准时 `role` 必填 |
| `POST /auth/switch-tenant` | 获批后切换到 10000 并刷新凭据 |

审核角色值为 `viewer`、`contributor`、`admin`。申请接口不接受申请人选择目标空间或角色。新增申请管理接口不对 API Key 开放。

## 数据与资源权限

保留 `tenants`、`users`、`tenant_members`、知识库、智能体、文档、会话及文件数据。申请存于 `tenant_join_requests`；未获批账号的 `users.tenant_id` 为空。

资源仅在当前授权知识空间内访问，角色、资源创建者、API Key 能力和知识库白名单继续共同约束读写。共享空间及跨空间知识库、智能体分享功能已删除，历史分享关系不能再授权访问。

## 升级

新增 PostgreSQL 116/117、SQLite 36/37 迁移。升级前确认 10000 已存在且状态为 active，飞书应用已启用并能返回初始化邮箱；停止旧版本请求并备份数据库，再运行新版迁移与服务。

共享关系删除后无法通过应用降级恢复，需使用升级前备份。申请与一次性初始化标记应永久保留，避免回滚后重复初始化。详见仓库 `deploy/TEAM_SPACE_MIGRATION.md`。
